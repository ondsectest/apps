A dictated password is saved in plain text in the transcript history

Security issueDictation, HistoryDesktop app, MacBook Pro

What happens (shown with mock data)

  1. On a sign-in page, the username is dictated with Wispr Flow: fine.
  2. In the password field, Wispr Flow does not warn or stop. The password is typed in, and the field shows dots.
  3. Wispr Flow's history now shows the password in plain text, like any other transcript.

Why it matters

  • Anyone with access to the computer or the account can read the password in history.
  • Depending on settings, the transcript may also be synced to the cloud or eligible for model training.
  • People do not expect a password field to be remembered anywhere.

Yes, warn, and never save what is dictated into a password field

ImprovementDictation, History

What changes

  • Wispr Flow detects a password field. macOS marks these as secure text fields, and browsers expose web password inputs the same way.
  • When fn is pressed there, the Flow Bar shows a clear warning: "This is a password field. Dictating a password lets people nearby hear it."
  • Two choices: Type it instead (default) or Dictate privately.
  • With Dictate privately, the text goes into the field, but nothing is saved: no history entry text, no cloud sync, no training, no clipboard. History shows only "Password field, not saved".
  • Optionally, the same protection for other secrets in any field, such as one-time codes, card numbers and API keys.

Why a warning alone is not enough

  • A warning can be dismissed. The real protection is never storing it, so even a hurried user is safe.
